# Конспект — 9. Шаблоны проекта

> Тема занятия из [таблицы курса](https://docs.google.com/spreadsheets/d/1mLdR4r9jjsBcKdaG77887BA6OdZc_tCmDNlfhJGdJfk/edit?gid=187801412). Связанные работы: Практика MVC — Ювелирный магазин на PHP (в репозитории), ПР 2.0–2.4.

## Что такое шаблон проекта

**Шаблон проекта (шаблонизация)** — отделение логики приложения от представления: данные готовит PHP, а страницу рисует шаблон с подстановкой переменных.

Без шаблонизации: HTML и PHP вперемешку в одном файле — невозможно менять дизайн без правки логики и наоборот.

## Шаблонизация в PHP

```php
// Раньше: логика и представление смешаны
$user = 'Алексей';
echo '<h1>Привет, ' . $user . '</h1>';
```

```php
// С шаблоном: include файла-шаблона
<?php include 'views/header.php'; ?>
<h1>Привет, <?= htmlspecialchars($user) ?></h1>
<?php include 'views/footer.php'; ?>
```

### Простые include-шаблоны vs шаблонизаторы

| Подход | Плюсы | Минусы |
|--------|-------|--------|
| include PHP-файлов | Просто, без зависимостей | Логика в шаблоне, нет наследования |
| Шаблонизатор (Twig, Smarty) | Синтаксис, фильтры, наследование, автозагрузка шаблонов | Оверхед, новая библиотека |

Пример наследования в Twig: `base.html` с блоками `{% block content %}` — дочерний шаблон перекрывает нужный блок.

## Архитектура MVC

**MVC (Model-View-Controller)** — разделение на три компонента:

| Компонент | Отвечает за |
|-----------|-------------|
| Model | Данные и логика: запросы к БД, правила |
| View | Отображение: HTML-шаблоны |
| Controller | Приём запроса, выбор модели и вида |

Поток запроса: `URL → роутер → контроллер → модель (данные) → вид (шаблон) → HTML клиенту`.

### Понятия проекта «Магазин на PHP»

- **Роутер (router)** — разбирает URL, выбирает контроллер и действие (см. ПР 2.1 в репозитории)
- **Контроллер** — функция/класс, обрабатывающий конкретный маршрут
- **Модель** — классы `Product`, `Cart` и запросы к БД (ПР 2.3)
- **Вид (шаблон)** — страницы каталога/товара/корзины

### Зачем MVC

1. Дизайн и данные разделены
2. Код читаем: файл = компонент
3. Правило единой ответственности: каждый класс делает одно
4. Переиспользование: один и тот же вид для разных данных
5. Лучше для команд: фронтендер и бэкендер работают с разными файлами
6. Повторное использование компонентов между проектами

## Структура типового проекта

```
project/
├── public/          # точка входа index.php, статика (css, js, images)
├── app/
│   ├── Controllers/
│   ├── Models/
│   └── Views/       # шаблоны
├── config/          # настройки, доступы к БД
├── vendor/          # composer-зависимости
└── router.php       # таблица маршрутов
```

Точка входа одна: все запросы идут через `public/index.php` — роутер дальше сам решает, какой контроллер вызвать. Это защищает файлы конфигурации от прямого доступа.

## Организация файлов CSS (по frontend)

- **Базовый/сброс** — normalize/reset, `body`, типографика
- **Компоненты** — кнопки, формы, карточки, шапка, подвал
- **Страницы** — стили конкретных страниц
- **Утилиты** — `.mt-1`, `.text-center` и мелкие хелперы
- **Адаптивность** — медиазапросы рядом с компонентом

## Термины

| Термин | Определение |
|--------|-------------|
| Шаблонизация | Подстановка данных в заранее подготовленный HTML-шаблон |
| Шаблонизатор | Библиотека шаблонов (Twig, Smarty, Blade) с наследованием |
| MVC | Model-View-Controller — разделение данных, представления и управления |
| Роутер | Разбор URL на контроллер/действие |
| Точка входа | Единый `index.php`, через который идут все запросы |
| Вид/View | HTML-шаблон страницы |
