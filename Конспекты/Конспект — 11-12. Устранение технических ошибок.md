# Конспект — 11-12. Устранение технических ошибок

> Тема занятия из [таблицы курса](https://docs.google.com/spreadsheets/d/1mLdR4r9jjsBcKdaG77887BA6OdZc_tCmDNlfhJGdJfk/edit?gid=187801412). Связанная ЛР — Лабораторная работа 2 — Техническая оптимизация znanium.com (в репозитории).

## Коды ответа сервера, которые должен знать SEO-специалист

| Код | Значение | Что делать |
|-----|----------|------------|
| 200 OK | Страница существует | — |
| 301 Moved Permanently | Переезд навсегда | Использовать при смене URL, склеивать с новым адресом |
| 302 Found | Временный редирект | Не использовать для постоянных изменений |
| 404 Not Found | Страница не найдена | Убрать битые ссылки, настроить 404-страницу |
| 410 Gone | Удалено навсегда | Сигнал роботу: не заходить больше |
| 500 Internal Server Error | Ошибка сервера | Срочно исправить; массово — почти стоп-индексация |
| 503 Service Unavailable | Временно недоступен (ТО) | Сообщить Яндексу/Google, чтобы не потерять позиции |

## Дубли страниц

**Дубль** — одна и та же информация доступна по нескольким URL. Робот раскладывает «вес» страницы на копии → позиции проседают.

### Причины дублей

1. Один документ с параметрами: `/catalog/?sort=price`, `?page=2`
2. Печатные версии `/print/123`, версии для печати
3. Уникальные параметры сессий/фильтров в URL
4. Страницы пагинации `/page/2/`, доступные через разные сортировки
5. Сайт доступен с `www` и без → два зеркала
6. Ссылки с `index.php` в конце: `/` и `/index.php`
7. Разные протоколы: `http://` и `https://`
8. Разные способы вывода одного товара в нескольких категориях

### Способы устранения

| Приём | Где применять |
|-------|---------------|
| `rel="canonical"` | Указать «материнский» URL: `<link rel="canonical" href="https://site.ru/catalog/">` |
| 301-редирект | Слепить `www`→без `www`, `http`→`https`, `/index.php`→`/` |
| `Disallow` в robots.txt | Закрыть служебные дубли (печать, сортировки) |
| `noindex, follow` | Дубли в индексе, которые нельзя закрыть в robots.txt |
| Настройка хостинга/.htaccess | Единая точка входа — единый URL |
| rel="alternate" | Для пагинации указать канон |

## Битые ссылки

**Битая ссылка** — ссылка на URL, отдающий 404/410 (или вовсе недоступный). Вред: посетитель уходит, робот тратит краулинговый бюджет.

### Как найти

- Яндекс.Вебмастер / Search Console → раздел «Битые ссылки»/«Ошибки обхода»
- Программы-краулеры: Screaming Frog, SiteAuditor, Xenu
- Плагины для CMS
- Логи сервера — ответы 404

### Что делать

1. **Восстановить** страницу (если нужна)
2. **301-редирект** на ближайшую актуальную (товар удалён → категория)
3. **Убрать ссылку** с сайта, если она больше не нужна
4. Сделать **умную 404** с поиском и топовыми разделами (не «голая»)
5. Проверить **внешние ссылки** — на битые попросить поправить у доноров

## Скорость загрузки (повторение с акцентом)

- Оптимизация изображений → WebP, thumbnails, lazy loading
- Минификация и объединение CSS/JS; `defer`/`async`
- Кэширование: Cache-Control/ETag, CDN для статики
- Серверная часть: TTFB от БД/кэша (см. [Конспект — 3. Оптимизация серверной части](%D0%9A%D0%BE%D0%BD%D1%81%D0%BF%D0%B5%D0%BA%D1%82%20%E2%80%94%203.%20%D0%9E%D0%BF%D1%82%D0%B8%D0%BC%D0%B8%D0%B7%D0%B0%D1%86%D0%B8%D1%8F%20%D1%81%D0%B5%D1%80%D0%B2%D0%B5%D1%80%D0%BD%D0%BE%D0%B9%20%D1%87%D0%B0%D1%81%D1%82%D0%B8.md))
- Метрики: LCP, CLS через PageSpeed Insights / Вебмастер
- Тяжёлые виджеты (метрики, чаты) — отложить/асинхронно

Технические ошибки → падение поведенческих факторов → падение позиций: поэтому техническая оптимизация обычно идёт **до** контентной.

## Термины

| Термин | Определение |
|--------|-------------|
| Дубль | Одна информация по разным URL |
| Canonical (rel="canonical") | Указание «основного» URL для страницы |
| 301-редирект | Постоянное перенаправление на новый адрес |
| 410 Gone | Страница удалена навсегда |
| Битая ссылка | Ссылка на несуществующий URL |
| Скраулинговый бюджет | Запас страниц, которые робот готов обойти за визит |
| 404-страница | Страница «не найдено» с навигацией по сайту |
